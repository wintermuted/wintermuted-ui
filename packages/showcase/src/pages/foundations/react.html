React components

Optional behavior, shared Wintermuted styles. The CSS-only package remains independent of React.

Document primitives

PageHeader uses canonical view-header styling; Breadcrumbs composes Nav and accepts a router-independent renderLink. PreviewImage renders a labeled fallback for missing or failed images and retries when src changes. All copy, icons, routes and content belong to the caller.

FilterPanel is a responsive non-modal disclosure, inline above 48rem and expandable on narrower viewports. Controls remain mounted. Escape within the disclosure, close and scrim dismissal restore toggle focus; it does not trap focus or lock scrolling. Use Dialog when modality is required.

Compose loading states with Spinner label="..." or a status Alert containing an icon and message. Compose error/recovery states with Alert role="alert" tone="danger", a heading, message and recovery content. Separate LoadingState and ErrorState exports are unnecessary.

Context-free controls

ToggleGroup, FacetFilter, SortableTableHeader, StatCard, RankedBarList, Toast, ColorPicker, NumberStepper and LanguageSelector accept application-supplied data and copy. Load the theme explicitly; no router, translation provider, storage or notification timer is required.

Choose StatCard variant="compact" for label-first metrics and ToggleGroup appearance="outline" for an outlined selector. Facet reset is independent of values named all. Sortable headers render their own th; sort and direction callbacks are separate.

Loading and action disclosures

LoadStatus announces supplied errors with an alert and warnings with a status. Idle renders nothing. Retry calls each supplied callback once and is disabled during loading. Optional help receives the exact combined message and error/warning tone; position it in the host.

RefreshAction composes Button, prioritizes loading over retry/idle labels, preserves native props and refs, and never submits a form. ActionDisclosure defaults expanded and keeps hidden content mounted. Its labeled header action is separate from the heading trigger and schedules expansion before its callback. Collapse cleanup runs before hiding; applications own post-render focus.

Use native Accordion for simple details/summary content and ActionDisclosure when a separate header action is required. Neither component owns fetching, routing or persistence.

Install only what you use

npm install @wintermuted/ui-theme@^1.0.0 @wintermuted/ui-react@^1.0.0 react react-dom
# Optional searchable multi-select:
npm install @wintermuted/ui-react-select react-select

Core React components and theme runtime helpers live in @wintermuted/ui-react; MultiSelect lives in @wintermuted/ui-react-select with its required react-select peer. The old @wintermuted/ui-react/select entry point is removed. The CSS-only theme has no React dependencies. Upgrading from 0.x? Follow the 1.0 migration guide after both packages are published.

import "@wintermuted/ui-theme/index.css";
import { Button, ThemeProvider, ThemeSelect } from "@wintermuted/ui-react";
import { MultiSelect } from "@wintermuted/ui-react-select";
import { initTheme } from "@wintermuted/ui-react/theme";

initTheme({ storageKey: "my-app:theme" }); // before createRoot
// Use the same key on ThemeProvider.

Native props and refs pass through primitives. Card slots, ListGroup, ListItem and Nav accept as for semantic markup or router links. No router dependency or grid framework is required.

Interaction contracts

Tabs use arrow keys, Home and End with roving focus. Menus use arrow keys, Enter, Escape and Tab. Dialog uses the browser's modal top layer, focus containment and Escape; the caller owns its open state. Accordions use native details/summary. Tooltips show on focus and hover and dismiss with Escape.

FieldGroup keeps hint and error content visible together and links both to the control, preserving existing descriptions. Supply hintId and errorId for explicit IDs. Dialog accepts titleId for its heading and a closeAction node to replace the default Close button. Custom close actions need an accessible name and must invoke the controlled close callback; native Escape handling and focus restoration remain unchanged.

Theme starts in System mode. Light/Dark overrides persist; returning to System follows OS changes. Put getThemeScript() in an inline head script with your CSP nonce for SSR first paint. Theme changes touch only document theme attributes and color-scheme, never map layers.
